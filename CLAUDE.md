# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Fabler is an interactive fiction (CYOA) creation and reading platform:

- **Creation tool** (`creation-tool/`): Tauri desktop app for authoring stories
- **Reader app** (`reader/`): Tauri desktop/mobile app for playing stories
- **Player** (`player/`): Shared TypeScript package — game engine + React UI components
- **Shared** (`shared/`): Rust crate — data types, bundle format, content model

## Tech Stack

- **Frontend**: React 18, TypeScript, Vite, Tailwind CSS 4, Jotai (state), Wouter (routing)
- **Backend**: Rust, Tauri 2.0 RC
- **Storage**: JSON files on disk (no database)
- **Content**: Markdown with `marked` for rendering
- **Testing**: Playwright (E2E), Vitest (unit), Rust `#[test]` (Rust unit/integration)

## Common Commands

```bash
# Creation tool
cd creation-tool
yarn dev                  # Vite dev server (port 1420)
yarn tauri dev            # Full Tauri app
yarn test:e2e             # Playwright E2E tests (builds + starts test server)
npx vitest run            # Unit tests

# Reader app
cd reader
yarn dev                  # Vite dev server (port 1421)
yarn tauri dev            # Full Tauri app

# Player package
cd player
npx vitest run            # Unit tests (25 engine tests)
npx playwright test       # E2E tests (13 player UI tests)

# Rust
cargo test                # All Rust tests (shared + creation-tool + reader)
cargo build -p creation-tool --features test-server  # Build test HTTP server
```

## Project Structure

### Storage Format

Stories are directories with JSON files:
```
my-story/
├── story.json                # Story metadata + flags
├── pages/
│   ├── a3f2b-entrance.page.json
│   └── b7c1d-dark-tunnel.page.json
└── assets/
    └── hero.png
```

- All IDs are 5-character lowercase hex strings
- `Story.id` is the story's stable identity. It is minted by `Project::create`,
  carried into exported bundles by `build_manifest`, and is what the reader keys
  installs and save slots by — so two stories must never share one. It is
  `#[serde(default)]`: story.json files written before ids existed load with an
  empty id, which `Project::open` backfills and persists.
- Page filenames: `{id}-{slugified-name}.page.json` (id is authoritative, name portion is cosmetic)
- Page bodies use a `Document` type containing a `Markdown` block with raw markdown source
- `.fabler` bundle = zip of `manifest.json` (all pages inline) + `assets/`

### Data Model (`shared/src/`)

- `models.rs`: `Story`, `Page`, `Choice`, `Flag`, `FlagOperation`, `Condition`, `PageListItem`
- `content.rs`: `Document`, `Block` (Paragraph, Blockquote, Image, HorizontalRule, Markdown), `Inline`, `Mark`
- `bundle.rs`: `Manifest`, `ManifestStory`, `build_manifest()`, `pack_bundle()`, `unpack_bundle()`
- `id.rs`: `generate_id()`, `generate_unique_id()`
- `migration.rs`: Format version migration framework (scaffolding)
- Types crossing into TypeScript are generated by ts-rs into `@fabler/types`.
  `yarn codegen` regenerates them; `yarn codegen:check` verifies freshness.
  The save-format types (`GameState`, `SavedState`, `SlotInfo`) serialise in
  camelCase via serde renames while everything else is snake_case — that is
  deliberate, see the type-generation design doc.

### Creation Tool Backend (`creation-tool/src-tauri/src/`)

- `project/mod.rs`: `Project` struct — opens/creates story directories, CRUD for pages/story/assets
- `project/pages.rs`: Page file I/O (read, write, list, delete, slugify)
- `project/story.rs`: Story file I/O
- `project/export.rs`: Bundle export (zip project into .fabler)
- `project/import.rs`: Bundle import (unzip .fabler into project)
- `commands.rs`: Tauri commands — `open_project`, `create_project`, `get_story`, `save_story`, `list_pages`, `get_page`, `save_page`, `create_page`, `delete_page`, `export_bundle`, `copy_asset`, `list_assets`, `delete_asset`, etc.
- `error.rs`: `AppError` enum
- `test_server.rs`: HTTP test server (only compiled with `test-server` feature)

### Creation Tool Frontend (`creation-tool/src/`)

- `api.ts`: Dual-mode API — Tauri `invoke()` in production, HTTP fetch in test mode (`VITE_USE_HTTP_API=true`)
- `types.ts`: Hand-written TypeScript types matching Rust models
- `atoms/`: Jotai state — `projectOpenAtom`, `storyAtom`, `pageListAtom`, `pageAtomFamily`, actions for save/create/delete
- `components/PageCard.tsx`: Main page editor (markdown editor, choices, flags, conditions)
- `components/MarkdownEditor.tsx`: Split-view textarea + live preview
- `components/ui/SelectWithCreate.tsx`: Generic select dropdown with inline "create new" option
- `components/layout/Sidebar.tsx`: Landscape sidebar
- `components/layout/BottomBar.tsx`: Portrait bottom bar with modal sections
- `player/PlaytestView.tsx`: Full-screen playtest overlay
- `player/PreviewView.tsx`: Side panel page preview
- `i18n/translations.ts`: All UI strings (never hardcode text in components)

### Player Package (`player/`)

- `engine/types.ts`: Manifest, game state, adapter interfaces (`StorageAdapter`, `AssetResolver`), Document/Block types
- `engine/runtime.ts`: Pure game logic — `navigate()`, `evaluateConditions()`, `applyFlagOperations()`, `getAvailableChoices()`
- `ui/StoryPlayer.tsx`: Top-level player component (supports `hideChrome` + imperative handle for external controls)
- `ui/ContentRenderer.tsx`: Renders Document → semantic HTML (handles markdown blocks via `marked`)
- `ui/PageView.tsx`, `ChoiceList.tsx`, `PlayerChrome.tsx`, `Settings.tsx`, `SaveLoadMenu.tsx`
- `ui/theme.css`: CSS custom properties for light/dark themes + font scaling (import this, not `player.css`, when embedding)

### Reader App (`reader/`)

- `src-tauri/src/library.rs`: Story library — install/list/delete .fabler bundles
- `src-tauri/src/storage.rs`: Save slot persistence (JSON files on disk)
- `src-tauri/src/commands.rs`: Tauri commands + `read_asset_base64` for image serving
- `src/screens/LibraryScreen.tsx`: Story grid
- `src/screens/PlayerScreen.tsx`: Mounts StoryPlayer with Tauri-backed adapters
- `src/components/PlayerBar.tsx`: Responsive nav bar (bottom on portrait, side on landscape)
- `src/adapters/TauriStorageAdapter.ts`, `TauriAssetResolver.ts`

## Development Workflows

### Adding a New Tauri Command

1. Add method to `Project` in `creation-tool/src-tauri/src/project/mod.rs`
2. Add `#[tauri::command]` function in `commands.rs`
3. Register in `invoke_handler` in `main.rs`
4. Add to `api.ts` in both `buildHttpApi()` and `buildTauriApi()`
5. Add match arm in `test_server.rs` invoke dispatch
6. If the command introduces a new Rust type, derive `TS` on it with
   `#[ts(export, export_to = "../../types/src/")]` and run `yarn codegen`.
   Never hand-write TypeScript for a Rust type — `types/` is generated and
   CI fails if it is stale.

### Adding New UI Text

1. Add key to `creation-tool/src/i18n/translations.ts`
2. Use `const { t } = useTranslation()` in component
3. Reference as `t.buttons.myKey`, `t.labels.myKey`, etc.

### Running E2E Tests

The creation tool E2E tests use a dual-mode setup:
1. `test-with-backend.sh` builds and starts a Rust HTTP test server on port 3001
2. The test server exposes a single `POST /api/invoke` endpoint that dispatches to `Project` methods
3. Vite runs with `VITE_USE_HTTP_API=true`, making `api.ts` use fetch instead of Tauri invoke
4. Playwright drives the browser against localhost:1420
5. Test helpers in `e2e/helpers.ts` use the `invoke()` pattern to set up test data

To add a command to the test server: add one match arm in `test_server.rs`.

### Player Package Usage

When embedding the player in another app:
- Import `@fabler/player/ui` for `StoryPlayer` component
- Import `@fabler/player/engine/types` for TypeScript types
- Import `@fabler/player/ui/theme.css` for CSS variables (NOT `player.css` which includes Tailwind)
- Add `@source "../../player/ui/**/*.tsx"` to your CSS for Tailwind class scanning
- Implement `StorageAdapter` and `AssetResolver` interfaces for your platform

### Image Assets

- Creation tool: images copied to project `assets/` dir via `copy_asset` command
- In-editor preview: `convertFileSrc()` resolves filenames to Tauri asset protocol URLs
- Requires `protocol-asset` Tauri feature + `assetProtocol` config in `tauri.conf.json`
- Bundle export: all files from `assets/` included in `.fabler` zip
- Reader: `convertFileSrc()` for serving images from app data directory

### Responsive Layout

Both apps use CSS `@media (orientation: portrait/landscape)` for layout switching:
- Portrait: bottom bar with icon buttons (modals for sections in creation tool)
- Landscape: sidebar
