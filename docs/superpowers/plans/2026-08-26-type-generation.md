# Rust → TypeScript Type Generation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Rust the single source of truth for every type crossing into TypeScript, and make drift impossible to commit.

**Architecture:** ts-rs 12.0.1 derives emit one `.ts` file per type into a new `@fabler/types` yarn workspace package. The save-format types move from the reader into `shared/` first, so the player never depends on reader-generated types. The three hand-written mirror files are deleted, and CI fails if regenerating changes anything.

**Tech Stack:** Rust, ts-rs 12.0.1, serde, TypeScript, yarn workspaces, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-08-26-type-generation-design.md`

## Global Constraints

- **This phase changes no runtime behaviour.** Generated output is semantically identical to what it replaces. If an e2e test fails, the change is wrong.
- Keep the camelCase serde renames on the save types (`gameState`, `slotId`, `currentPageId`) exactly as they are. They make generated TS match existing TS character for character. Normalising the save wire format is explicitly out of scope.
- `export_to` paths are relative to the **source file's directory**, not the crate root. A crate-root-relative path silently writes outside the repository.
- ts-rs generates **no index file**. The index is generated by a script; never hand-write it.
- eslint must stay at 0 errors, 0 warnings. `tsc --noEmit` must stay clean in all three packages.
- Do not generate command bindings, do not normalise the save format, do not prettify generated output — all explicit spec non-goals.

**Files:**

**Interfaces:**

- [ ] **Step 1: Create the module**

Create `shared/src/save.rs`:

```rust
use std::collections::HashMap;

use serde::{Deserialize, Serialize};

/// Player-facing save format, shared by the player engine and the reader's
/// on-disk save slots.
///
/// These three types serialise in camelCase, unlike every other type in this
/// crate. That is deliberate and load-bearing: the player's TypeScript has
/// always used camelCase here, and the renames are what let the generated
/// bindings match it exactly. Normalising the wire format is tracked
/// separately in docs/TODO.md.
#[derive(Debug, Serialize, Deserialize, Clone)]
pub struct GameState {
    #[serde(rename = "currentPageId")]
    pub current_page_id: String,
    pub flags: HashMap<String, bool>,
}

#[derive(Debug, Serialize, Deserialize, Clone)]
pub struct SavedState {
    #[serde(rename = "gameState")]
    pub game_state: GameState,
    pub name: String,
    pub timestamp: u64,
}

#[derive(Debug, Serialize, Deserialize, Clone)]
pub struct SlotInfo {
    #[serde(rename = "slotId")]
    pub slot_id: String,
    pub name: String,
    pub timestamp: u64,
}
```

Add `pub mod save;` to `shared/src/lib.rs`, in alphabetical position (after `models`).

- [ ] **Step 2: Point the reader at it**

In `reader/src-tauri/src/storage.rs`, delete the three local struct definitions (`GameStateData`, `SavedState`, `SlotInfo` — currently lines 8-29) and replace them with a re-export, so `crate::storage::SavedState` keeps resolving for `commands.rs`:

```rust
pub use shared::save::{GameState, SavedState, SlotInfo};
```

`GameStateData` is renamed to `GameState` in the move. Update every reference to it in `storage.rs` and anywhere else in the reader. `use std::collections::HashMap;` may become unused — remove it if so.

- [ ] **Step 3: Verify the move changed nothing**

Run: `cargo test --workspace`
Expected: 52 tests pass. The reader's storage round-trip tests are the ones that matter — they assert the on-disk JSON shape, so if a serde rename was dropped in the move, they fail.

- [ ] **Step 4: Commit**

```bash

git commit -m "refactor(shared): move save-format types out of the reader"

```

Expect ts-rs 12.0.1.

- [ ] **Step 2: Create the package**

Create `types/package.json`:

```json
{
  "name": "@fabler/types",
  "private": true,
  "version": "0.1.0",
  "type": "module",
  "types": "./index.ts",
  "exports": {
    ".": "./index.ts",
    "./*": "./src/*.ts"
  }
}
```

Create `types/src/.gitkeep` (empty file) so the directory exists before the first generation run.

Create `types/generate-index.mjs`:

```javascript
// ts-rs emits one file per type and no index. This regenerates the barrel
// from whatever is actually in src/, so a newly derived type cannot be
// forgotten — a hand-written index would be exactly the drift this package
// exists to prevent.
import { readdirSync, writeFileSync } from "node:fs";
import { dirname, join } from "node:path";
import { fileURLToPath } from "node:url";

const here = dirname(fileURLToPath(import.meta.url));
const srcDir = join(here, "src");

const names = readdirSync(srcDir)
  .filter((f) => f.endsWith(".ts"))
  .map((f) => f.replace(/\.ts$/, ""))
  .sort();

const body = [
  "// Generated by types/generate-index.mjs. Do not edit this file manually.",
  ...names.map((n) => `export type { ${n} } from "./src/${n}";`),
  "",
].join("\n");

writeFileSync(join(here, "index.ts"), body);
console.log(`types: indexed ${names.length} generated types`);
```

Add `"types"` to the `workspaces` array in the root `package.json`, and add these scripts:

```json
    "codegen": "cargo test --workspace export_bindings && node types/generate-index.mjs",
    "codegen:check": "yarn codegen && git diff --exit-code types/",
```

- [ ] **Step 3: Derive on the 21 types**

For each type below, add `TS` to its existing `derive` list and add an `#[ts(...)]` attribute. Add `use ts_rs::TS;` to each file's imports.

In `shared/src/models.rs`, `content.rs`, `bundle.rs`, `validation.rs` and `save.rs` the attribute is:

```rust
#[ts(export, export_to = "../../types/src/")]
```

In `reader/src-tauri/src/library.rs` it is one level deeper:

```rust
#[ts(export, export_to = "../../../types/src/")]
```

These paths are relative to the **source file's directory**. Getting this wrong writes files outside the repository without any error.

Derive on exactly these, and nothing else:
- `models.rs`: `Story`, `Flag`, `Page`, `Choice`, `FlagOperation`, `Condition`, `PageListItem`
- `content.rs`: `Document`, `Block`, `Inline`, `Mark`
- `bundle.rs`: `Manifest`, `ManifestStory`
- `validation.rs`: `Severity`, `ProblemDetail`, `Problem`, `Report`
- `save.rs`: `GameState`, `SavedState`, `SlotInfo`
- `reader/src-tauri/src/library.rs`: `InstalledStory`

Do NOT derive on `BundleContents`, `BundleError` or `StoryContext`. The first two never reach the frontend; the third is a borrowed lifetime type.

Leave every existing `#[serde(...)]` attribute untouched — ts-rs reads them, and they are what make the output match the current TypeScript.

- [ ] **Step 4: Generate and inspect**

Run: `yarn codegen`
Expected: 21 files in `types/src/`, plus `types/index.ts` reporting 21 types.

Then verify three specific outputs by reading them, because they are the ones whose serde attributes matter most:
- `types/src/Severity.ts` must be `export type Severity = "error" | "warning" | "info";`
- `types/src/ProblemDetail.ts` must be a union of object types each carrying a `"code"` property.
- `types/src/SavedState.ts` must use `gameState` (camelCase), not `game_state`.

If any of those is wrong, a serde attribute was disturbed — fix the Rust, do not edit the generated file.

- [ ] **Step 5: Prove the freshness check works**

Temporarily add a field to `shared/src/models.rs`'s `Flag` (e.g. `pub description: String,`), run `yarn codegen:check`, and CONFIRM IT FAILS with a diff in `types/`. Then revert the field, re-run, and confirm it passes. Paste both outputs into your report — a check that cannot fail is not a check.

- [ ] **Step 6: Commit**

```bash
git add types package.json yarn.lock shared reader/src-tauri Cargo.lock
git commit -m "feat(types): generate TypeScript bindings from Rust with ts-rs"
```

// Types that cross the Rust boundary are generated — see @fabler/types.
// Re-exported here so `@fabler/player/engine/types` stays a complete public
// API for embedders who have not installed @fabler/types directly.
export type {
  Manifest,
  ManifestStory,
  Flag,
  Page,
  Choice,
  FlagOperation,
  Condition,
  Document,
  Block,
  Inline,
  Mark,
} from "@fabler/types";

// reference them. Exporting them twice would be a duplicate-export error.
import type { GameState, SavedState, SlotInfo } from "@fabler/types";
export type { GameState, SavedState, SlotInfo };

// -- Types with no Rust counterpart --

/** Convenience alias; Rust expresses this inline as HashMap<String, bool>. */
export type FlagState = Record<string, boolean>;

export interface StorageAdapter {
  saveSlot(storyId: string, slotId: string, state: SavedState): Promise<void>;
  loadSlot(storyId: string, slotId: string): Promise<SavedState | null>;

export type Theme = "light" | "dark" | "system";

export interface UserPreferences {
  fontSize: FontSize;
  theme: Theme;
}

export const DEFAULT_PREFERENCES: UserPreferences = {
  fontSize: "medium",
  theme: "system",
};
